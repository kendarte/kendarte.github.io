Project architecture

Action, consequence and persistent context.

Siza is structured as a systems project rather than a single isolated prototype.

Adventure layer

Visual MUD exploration.

The adventure mode treats locations, NPCs, objects and actions as persistent world state instead of disposable story prompts.

Combat layer

Card-driven encounters.

The TCG mode translates characters, summons, reactions, equipment and resources into a separate tactical ruleset connected to the same setting.

World layer

Worldbook-grounded AI.

Rivarica provides the structured knowledge base used to keep places, factions and setting logic coherent while the AI game master responds dynamically.

Design goal

Action and consequence.

Player actions are intended to create persistent reactions in the world: hostility, faction responses, changing access, encounters and new narrative states.

Current result

A connected prototype ecosystem.

The public project already includes a browser-based TCG prototype, an AI-driven MUD prototype, the Rivarica World Book and a dedicated atlas. The long-term work is to bring those layers into one persistent RPG experience.

System relationship

World → action → rules → consequence.

  1. 01Worldbook

    Defines the setting and available context.

  2. 02Adventure

    The player acts inside persistent locations and situations.

  3. 03Resolution

    Checks, combat and card systems resolve uncertainty and conflict.

  4. 04AI response

    The game master interprets the result in world context.

  5. 05Persistence

    The consequence becomes part of the next state.
