Case study

Keep story progression inside player control.

The slice needed deliberate hand-offs between exploration and staged narrative so the player always knew what changed and what to do next.

Problem

Separate features did not yet form one investigation.

First-person movement, doors, discovered items, dialogue choices, objective messages and scene progression worked individually but lacked one shared flow.

Constraints

Every state change had to remain readable.

Staged sequences needed to take control safely, blocked routes needed useful feedback and each completed interaction needed to update the investigation without duplicate events.

Decision

Model exploration and narrative as explicit phases.

A shared investigation state coordinates player input, cursor ownership, dialogue, objectives and environmental gates. Each phase defines entry, exit and recovery behavior.

My contribution

Vertical-slice implementation across disciplines.

I assembled and programmed first-person control, interactions, dialogue presentation, objective feedback, scene progression and technical integration.

Debugging evidence

Continuity breaks on small mistakes.

These examples turn a vague “narrative integration” claim into concrete engineering work.

BUG / INPUT

The cursor stayed unlocked after dialogue.

An interrupted conversation bypassed the normal exit path and returned camera control without restoring cursor ownership.

Fix: moved input restoration into a shared phase-exit routine.
BUG / OBJECTIVES

One clue created duplicate objective updates.

Both interaction completion and animation completion published the same investigation event.

Fix: made progression events idempotent and keyed by clue ID.
BUG / WORLD STATE

A solved door locked again after a staged scene.

Scene presentation restored serialized defaults instead of the current investigation state.

Fix: re-applied environmental state from the shared progression model.
BUG / HAND-OFF

The player could move during the opening shot.

Movement input was disabled one frame after the cinematic began, allowing a visible positional jump.

Fix: acquired the control lock before starting camera and dialogue tracks.

Investigation flow

Every phase has an owner and an exit.

Exploration, interaction and dialogue share progression state while controlling input, cursor, camera and feedback deliberately.

  1. BriefSet the current case, objective and initial environmental state.
  2. ExploreGrant first-person movement, camera and interaction authority.
  3. InvestigateResolve objects through stable IDs and publish readable feedback.
  4. ChooseTransfer input to dialogue and stage the character exchange.
  5. AdvanceCommit progression, update gates and restore first-person control.
