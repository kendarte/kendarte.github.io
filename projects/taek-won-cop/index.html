Case study

Stop multiple systems from competing for the player.

The difficult part was not adding another attack. It was deciding who owns input, movement, animation and camera state at every transition.

Problem

Every framework assumed it was in charge.

Combat input, RPG statistics, enemy reactions, cinematics and narrative sequences could interrupt each other, producing stuck locomotion, duplicate actions and broken camera restoration.

Constraints

Keep commercial middleware intact.

The custom layer had to coexist with Invector, Adventure Creator, Koreographer, SALSA, ARPG statistics and destructible-environment tools without modifying or redistributing their source.

Decision

Introduce explicit adapters and state ownership.

Dedicated bridges arbitrate attack spaces, temporary control locks, reaction state, cinematic tracks and restoration. Game rules remain outside third-party components.

My contribution

Gameplay architecture through working presentation.

I designed and programmed the coordination layer, combat behavior, target snap, defense outcomes, status effects, cinematic control and debugging workflow.

Result

A reviewer can inspect both behavior and boundaries.

The captures show combat, interaction, destruction, facial performance and the in-world menu running in Unity. The public repository exposes Director and Clash Snap as coherent code-review samples while documenting every omitted dependency.

Debugging evidence

The bugs that defined the architecture.

These examples show the level of technical specificity expected in a production-facing portfolio.

BUG / TARGETING

Snap selected an enemy behind cover.

Range and view angle passed, but the final target did not require a clean line of sight.

Fix: added occlusion validation before the controlled approach.
BUG / CAMERA

Cinematic exit restored the wrong camera.

Nested sequences overwrote the previous-camera reference and returned the player to an obsolete shot.

Fix: replaced one reference with a scoped camera-state stack.
BUG / INPUT

Defense left the player permanently locked.

An interrupted guard-break path skipped cleanup when the target was removed mid-reaction.

Fix: centralized restoration in an idempotent recovery routine.
BUG / ANIMATION

Rapid attacks produced duplicate hit windows.

Animation events from the cancelled action remained valid after a new skill became active.

Fix: bound damage windows to the current action token.

Architecture

Foundation below, game rules above.

Middleware supplies stable capabilities. The custom layer owns game-specific decisions and coordinates transitions through narrow adapters.

  1. Input arbitrationChoose normal attack, Clash skill, Power Clash or Defender before movement begins.
  2. Target validationApply direction, lock-on, range, view angle and line-of-sight rules.
  3. Action ownershipGrant one skill authority over movement, animation, timing and damage.
  4. Reaction stateOverride enemy behavior temporarily and restore AI through one recovery path.
  5. PresentationTrigger camera, VFX, audio and time effects from resolved gameplay state.
