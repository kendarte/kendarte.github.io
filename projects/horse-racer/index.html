Case study

Replace 315 hand-built races with one source of truth.

The same configuration needed to control simulation, cameras, UI, filenames and batch progression without scene duplication.

Problem

Manual variation did not scale.

Ten horses produce 45 unique pairings. Seven finish conditions expand the matrix to 315 results, making hand-authored setup and recording slow and error-prone.

Constraints

Every subsystem had to agree on the result.

Independent lanes, exact finish timing, camera coverage, winner UI, deterministic filenames and Unity Recorder needed one shared race definition.

Decision

Make the race ID authoritative.

A bounded ID maps to pairing and outcome. Assigned duration drives movement while the same state informs cameras, presentation and recording.

My contribution

Simulation through editor workflow.

I designed and programmed orchestration, duration-based movement, cinematic direction, track generation, presentation, custom inspectors and batch capture.

Result

A repeatable content pipeline instead of duplicated scenes.

A reviewer can watch one complete automated race, inspect the mapping and movement model, and trace the same race definition through result display and exported filename.

Debugging evidence

Automation fails in the seams.

These examples show how a production pipeline becomes trustworthy enough to run without constant supervision.

BUG / TIMING

Photo finishes drifted between machines.

Frame-dependent acceleration reached the final waypoint at slightly different times under variable load.

Fix: derived normalized progress from assigned duration and measured lane distance.
BUG / CAMERA

The director bounced between two shots.

Near-threshold progress values repeatedly qualified adjacent presets during a close race.

Fix: added shot history, hysteresis and minimum hold duration.
BUG / RECORDING

Exported files inherited the next race ID.

Batch progression advanced state before Unity Recorder finished finalizing the current capture.

Fix: moved progression behind the recorder completion callback.
BUG / RESULT

Dead heats produced two winner events.

Each lane reported completion independently before the orchestrator resolved the shared outcome.

Fix: centralized finish resolution and made result publication idempotent.

System flow

One ID, one reproducible result.

The race definition is data. Movement, cameras, UI and recording consume it instead of inventing separate versions of the truth.

  1. Map IDResolve one of 45 pairings and one of seven finish conditions.
  2. ConfigureActivate two horses and assign lane-specific finish durations.
  3. SimulateConvert measured path length and duration into normalized movement.
  4. DirectSelect progress-driven shots with stable transitions and photo-finish coverage.
  5. RecordExport a deterministic filename, confirm completion and advance the batch.
